

# epoll

注册感兴趣的 FD 及事件（可读、可写等），用 `epoll_wait` 等待**就绪**通知；收到通知不等于 I/O 已替你完成。LT 在就绪条件仍满足时可继续报告；ET 报告状态变化，通常配合非阻塞 I/O 读写到 EAGAIN。[epoll(7)](https://man7.org/linux/man-pages/man7/epoll.7.html)。

目的是为了减少轮询, 仅在有数据的时候被唤醒, 进行读取操作.


# io_uring

1. **提交队列（SQ, Submission Queue）**：
    - 用户程序将 I/O 请求（如读、写）放入 SQ。
2. **完成队列（CQ, Completion Queue）**：
    - 内核将处理完成的 I/O 结果放入 CQ。
    - 用户程序从 CQ 中获取结果。

SQ 提交的是操作描述（SQE，含缓冲区地址等）；CQ 返回完成条目（CQE，含结果码/字节数及 user_data 等），**并不是把读写的数据正文装进 SQ/CQ**。数据缓冲区须按操作要求保持有效。[io_uring(7)](https://man7.org/linux/man-pages/man7/io_uring.7.html)。

队列一般使用<u>基于环形缓冲区的无锁队列</u>.

可批量提交并异步收取完成结果，减少系统调用与等待成本；主动等待完成等路径仍可能阻塞，不保证使用 io_uring 的进程全程不阻塞。
